# RF-007: Verificación de Identidad de Usuario

## Descripción
Como administrador del sistema deseo verificar la identidad de un usuario cuando es creado, de manera que pueda certificar que solo usuarios verificados pueden realizar publicaciones y ofertas en la plataforma.

## Patrón Utilizado

| Requerimiento | RF-007 |
| Patrón utilizado | Arquitectura Dirigida por Eventos (Choreography) |
| Justificación | Se utiliza para desacoplar el proceso de creación de usuario de la verificación externa y las notificaciones. Esto permite escalar independientemente y cumplir con la restricción de no usar hilos/procesos concurrentes en el microservicio. |
| Atributos de calidad favorecidos | Escalabilidad, Disponibilidad, Desacoplamiento. |
| Atributos de calidad desfavorecidos | Complejidad de rastreo, Consistencia eventual. |
| Componentes involucrados | Users Microservice (C-001), SNS UserEvents (C-005), Lambda VerificationTrigger (C-006), Lambda NotificationService (C-008), TrueNative (C-007). |

## Proceso Paso a Paso

1. **Creación**: El usuario envía una petición `POST /users`. El microservicio persiste el usuario con estado `POR_VERIFICAR`.
2. **Publicación**: Se publica un evento `USER_CREATED` en SNS.
3. **Disparo**: La Lambda `VerificationTrigger` se activa y solicita la verificación a TrueNative enviando un webhook de retorno.
4. **Respuesta Asíncrona**: TrueNative procesa la solicitud y llama al webhook `PATCH /users/verify/callback` en el microservicio de usuarios.
5. **Actualización**: El microservicio valida el token de seguridad, actualiza el estado del usuario y publica un evento `VERIFICATION_COMPLETED`.
6. **Notificación**: La Lambda `NotificationService` se activa y envía un correo electrónico al usuario a través de **Gmail SMTP**.
