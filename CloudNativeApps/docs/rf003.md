
# Requerimiento RF-003: Crear Publicación (Post)

Este requerimiento permite a un usuario crear una publicación de trayecto (post) en la plataforma. El servicio implementa un patrón de **Orquestador** para coordinar la validación y creación de rutas y publicaciones, asegurando la consistencia y evitando duplicados.

## Patrón Utilizado

| Requerimiento | Patrón utilizado | Justificación | Atributos de calidad favorecidos | Atributos de calidad desfavorecidos | Componentes involucrados |
| :--- | :--- | :--- | :--- | :--- | :--- |
| RF-003 | Orquestador / Agregador | Centraliza la lógica de validación y creación, evitando duplicados y side effects innecesarios. | Consistencia, Separación de responsabilidades | Disponibilidad (depende de múltiples servicios) | rf003-app, users-app, routes-app, posts-app |

## Componentes Nuevos

| Componente | Código/Id | Tipo | Responsabilidad | Integraciones |
| :--- | :--- | :--- | :--- | :--- |
| RF-003 Orchestrator | `rf003-app` | Microservicio | Coordina el flujo de creación de publicaciones: valida usuario, valida fechas, obtiene o crea ruta, verifica duplicados y crea publicación. | `users-app`, `routes-app`, `posts-app` (REST) |

## Proceso de Solución (Paso a Paso)

1. **Autenticación**: El usuario envía su token en el header `Authorization`. `rf003-app` valida el token con `users-app`.
2. **Validación de Fechas**: Se validan las fechas del trayecto y expiración antes de crear la ruta (fail-fast).
3. **Obtención o Creación de Ruta**: Se consulta `routes-app` para obtener o crear la ruta asociada al trayecto.
4. **Verificación de Duplicados**: Se consulta `posts-app` para asegurar que el usuario no tenga otra publicación para la misma ruta y fecha.
5. **Creación de Publicación**: Se crea la publicación en `posts-app`.
6. **Respuesta**: Se retorna la publicación creada y un mensaje de éxito.

## Endpoints Principales

- `POST /rf003/posts` — Crea una nueva publicación de trayecto.
- `GET /health` — Healthcheck del servicio.

## Manejo de Errores

- 401 Unauthorized: Token inválido o expirado.
- 403 Forbidden: Falta el header de autorización.
- 412 Precondition Failed: Fechas inválidas, duplicado o expiración incorrecta.
- 503 Service Unavailable: Error en servicios dependientes o error inesperado.

## Guía de Despliegue

Para desplegar estos cambios en EKS, siga estos pasos:

### 1. Preparar Imágenes
Construya y suba las imágenes al repositorio ECR:

```bash
# Login ECR
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin AWS_ACCOUNT_ID.dkr.ecr.us-east-1.amazonaws.com

# RF-003 App
docker build -t AWS_ACCOUNT_ID.dkr.ecr.us-east-1.amazonaws.com/rf003-service:v1.0.0 ./rf003_app
docker push AWS_ACCOUNT_ID.dkr.ecr.us-east-1.amazonaws.com/rf003-service:v1.0.0
```

### 2. Despliegue en K8s
Aplique los manifiestos:

```bash
kubectl apply -f k8s/
```
